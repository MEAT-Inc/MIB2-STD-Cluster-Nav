Runtime collection retry
========================
Keep BOTH updated files together in scripts/ on the connected laptop:
  collect_delphi_runtime.py
  delphi_inventory.py
The targeted script now requires the updated shared TelnetReader interface.

From the project folder:
  py -3 .\scripts\collect_delphi_runtime.py --stage-boot-files
Use python instead of py -3 if that is your working Python command.

Both collectors default to the project's delphi-dump folder (parent of scripts/),
independent of launch directory. --output remains an explicit override.
Existing files are never replaced. Each run keeps its own _collection_*/ reports.

Current result: libscreen.so.1 downloaded successfully (110740 bytes). The
remaining screen-cda/libXSAL failures are Telnet command-completion timeouts,
not failures to locate the files. The missing /usr/lib/graphics candidate is
normal; the actual library was found in /extbin/apps/usr/lib/graphics.

The revised script shows search and Telnet progress. Commands and received
bytes are flushed immediately to staging-actions.txt after authentication.
A staging timeout stops use of that shell session rather than repeating the
same wait for the next file. FTP files continue independently.
Telnet has a separate10-second timeout, adjustable with --telnet-timeout.
Do not increase it blindly if no command response is arriving; inspect logs.

--stage-boot-files uses root Telnet to copy allowlisted /proc/boot files into
a fresh /ramdisk/delphi-stage_<random identifier>/ folder, then FTP downloads
the copies. Only new temporary files are written. Originals, firmware, coding
and running services are unchanged. Temporary copies remain until reboot.
No cleanup/delete commands are issued. Staged source data is capped at8MiB.

Default FTP:192.168.1.4:21, ftpuser/ftpuser. Telnet:port23, user root. If asked,
use your working root password, or Enter for the blank password used previously.
--ask-password and --ask-telnet-password prompt upfront. Authentication exchanges
are not written into transcripts.

Review _collection_*/runtime-targets.json:
  target_availability: available_locally or not_collected for each target
  all_targets_available: whether all three target basenames have usable copies
  missing_basenames: discovery-only; an empty list does NOT mean downloads worked
  transfers: maps temporary transfer paths to original source paths
The general summary can report PARTIAL when an existing local destination is
skipped. Such a skip is not a transfer failure or verification against today's
car contents. Nonempty local copies with matching listed sizes are reported as
available; manifests distinguish fresh downloads from prior existing files.

If collecting on a separate laptop, merge its delphi-dump folder into the
workspace and keep all _collection_*/ folders. Existing empty .part files are
not complete binaries and will not be used as successful acquisitions.

15 focused offline tests pass. These changes have NOT yet been vehicle-tested.
If a retry still times out, preserve collection.log and staging-actions.txt;
they should now contain the actual received shell response and failure phase.
