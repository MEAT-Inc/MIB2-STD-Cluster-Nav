New runtime evidence:
- An app exit(7) is reported by this manager as raw wait status 1792 (7 << 8).
  It appends -X1792, not -X7, to the next launch. Preserve this verbatim.
- SIGINT to the owned synthetic app is reported as status 2 and restarted with
  -X2. Header/runtime SIGINT agrees with the signal 2 loaded in the captured
  manager's termination helper at 0x103d48 before kill at 0x103d4c.
- The manager restarts the fixture via a temporary namespace redirect, the wrapper
  removes the redirect before exec, and the observer records nine registrations.
  The observed child's parent remains the actual captured manager.
- The next manager restart executes the original fixture path with no observer.
  Its zero exit is not restarted during a bounded 1.5 second observation window.
- The unchanged observer candidate has SHA256 cc425ccdc1a889caa2b4128a0a55f07cc8b26679065d7e293b274b80e83ad70c.
- Six Python evidence-review tests reject wrong parent identity, normalized -X7,
  observer leakage, unexpected fatal signals and missing restoration evidence.

Interpretation:
We now have actual-manager evidence for the restart/injection/restoration sequence,
which is stronger than the previous model. This supplies a practical candidate
restart route without inventing a per-app stop command. It does not establish a
cooperative graceful stop: event 0x163 remains a manager shutdown request, while
AndroidAuto's 0x164 EV_APP_EXIT handler cleans up listeners of an exited app.
No claim is made that SIGINT gracefully shuts down real AndroidAuto.
