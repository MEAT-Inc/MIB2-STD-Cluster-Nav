Static control evidence (captured procman SHA256 c32c018b515396bd0b322fb2014b45f2fba37d6000b2d178e9dc402c6845f05d):
- Configuration parser -r sets descriptor+0x2c at 0x1038b8.
- Active exit handler 0x104260..0x10429c schedules a restart when that flag and
  recorded exit code are nonzero, subject to global shutdown state at 0x12ff70.
- Spawn worker 0x10433c calls spawnp at 0x104504, inherits environment, and preserves
  configured arguments. Nonzero recorded exits add an -X%d argument.
- EV_START_APP 0x161 selects an app ID; no per-app environment override is visible.
- EV_GET_APP_STATE 0x168 replies with event 0x169 and two words {appID,state}.
- The active-state shutdown branch at 0x104190 sends event 0x163 to the app with
  zero payload when configured exit countdown is positive. This is not yet a
  verified externally usable manager stop request. Do not send guessed events.

Static AndroidAuto evidence (expected SHA256 da1fd5776f6b85962b84ad77c6f564d3f09dd8079652229cda57b4138060c271):
- Event accessor 0x1064c0 reads message-header event at +0xc without conversion.
- Dispatcher at 0x1105c0 compares event 0x164 and branches to 0x112328.
- That handler reads payload word0, logs EV_APP_EXIT / appId at 0x112384 and calls
  0x1129bc with the app ID at 0x1123bc.
- 0x1129bc iterates the listener collection at this+0x2c, compares listener app IDs,
  and destroys/removes matching entries. This is listener cleanup, not proof of a
  command that terminates AndroidAuto. Its EV_APP_EXIT string must not be confused
  with procman's 0x163 shutdown request.
- scripts/trace_android_shutdown.py checks the binary hash and emits candidate
  references/windows using a reviewed function-local PIC-base invariant. It is
  heuristic static analysis, not a runtime protocol validation.
