Confirmed from this P0890D dump
-----------------------------
1. Native video route: isoTX filename is passed into encoder initialization;
   descriptor open/store, transport-buffer write, and close are traced. Stream
   is188-byte MPEG-TS with H.264 ES PID0x11, PMT PID0x10, PCR PID0x1000.
   Reconstructed PAT/PMT CRCs match constants in the actual binary.
2. Transport writes copy input synchronously. Full queue yields zero bytes
   written/EOK, not an ordinary retryable errno. One writer per channel is
   enforced; a second independent writer cannot safely take over the channel.
   Partial-block read and retained IOV lifetime are traced. Abnormal reader
   close and complete MOST consumer lifecycle remain unaudited.
3. Android Auto advertises protocol1.3. Its service registration is generic.
   The old discovery schema lacks modern cluster display metadata. A host-only
   wire fixture appends a secondary descriptor preserving the main bytes.
4. Discovery marshalling uses a16-byte IoBuffer and a00 06 message prefix.
   The downstream queue copies the message synchronously before caller cleanup.
   A host allocator model exercises replacing only the backing buffer while
   preserving original output on failure. This is NOT a native runtime shim.
5. The Java HMI conversion produced19,406 classes and414 were decompiled for
   targeted inspection. This passed ZIP/class-magic checks and selected javap
   parsing, not full bytecode verification or recompilation.
6. Phone-route status, cluster information state and native map-video ownership
   are separate. InfoStates emits BAP state6 during phone guidance. A future
   change must not globally falsify phone navigation state. DisplayManagement
   has asynchronous activate/rate/deactivate control and MAIN-map exclusion.

Important hook limitation
------------------------
The discovery marshaller call is through a PLT relocation, with GLOBAL/DEFAULT
visibility and no DT_SYMBOLIC/DT_FLAGS/DT_FLAGS_1 tags. That does NOT establish
LD_PRELOAD interception: QNX6.5 documents own-object lookup before preload
objects for shared-object symbol resolution. Runtime loader behavior remains
unproven. An application->library boundary or a reversible diagnostic probe
must be evaluated before choosing a hook mechanism.
https://www.qnx.com/developers/docs/6.5.0SP1/neutrino/lib_ref/d/dlopen.html
